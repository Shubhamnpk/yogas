# YoGas — production pass

## 1. One cylinder per person, per round

When a depot allots a cylinder to a consumer, every other waiting request that consumer has at any depot is automatically cancelled (status `cancelled`, with a notification explaining why). This stops people holding places in five queues at once.

- Handled inside the allotment routine in the database so it is atomic and cannot be bypassed from the app.
- Cancelled-by-system entries get a clear message: "Cancelled automatically — you were allotted a cylinder at <depot>."
- Once collected, the consumer can join a new queue again.

## 2. Profile page

New `/profile` page for both roles:
- Name, username, citizenship number (masked with a reveal toggle), address, district, phone, email.
- Editable, with save + validation.
- Consumer: their **collection code** (short human-readable code) and their QR code, with copy and download.
- Dealer: depot code, depot QR, and a link to depot settings.
- Sign out lives here too.

Consumers get a short collection code (e.g. `GQ-4F7K2A`) stored on their profile so a dealer can verify them by typing the code when a camera is unavailable. Dealer scan screen accepts this code as manual entry.

## 3. Floating QR button

A persistent floating action button on every signed-in screen:
- Consumer: opens their collection QR + code in a sheet.
- Dealer: opens the depot QR + depot code (the one consumers scan).

## 4. Depot search defaults to the user's district

- District is captured during consumer onboarding (and editable in the profile).
- `/dealers` opens filtered to the consumer's own district, with a one-tap "All districts" escape hatch and an empty-state hint when their district has no depots.

## 5. Single cylinder type

14.2 kg is the only size. Removes the cylinder-type selector from the join form and from dealer views; existing entries keep their stored value, and the label just reads "14.2 kg cylinder" everywhere. Quantity stays.

## 6. Real demo data instead of fake depots

- Delete the six placeholder depots and any orphaned waitlist entries/notifications tied to them.
- Create exactly two working demo logins:
  - **Consumer** — `demo.consumer@YoGas.app` / `demo1234`, profile fully completed (name, citizenship no., address, district Kathmandu).
  - **Dealer** — `demo.dealer@YoGas.app` / `demo1234`, owning one real depot: "Kathmandu Gas Depot", Kathmandu, stock 25.
- Both accounts are created with confirmed emails so they log in immediately.
- The landing page and auth page show these credentials in a small "Try the demo" card, one tap to fill the form.

## 7. Bug sweep / completion pass

- Guard against joining the same depot twice and against joining while already allotted elsewhere.
- Queue position refreshes after every action; dealer queue and stock counters stay in sync after allot/cancel/collect.
- Stock cannot go negative; allot blocked with a clear message when stock is short.
- Cancel restores stock only for allotted entries (already true) and is reflected instantly in the UI.
- Scanner: manual code entry fallback on both scan screens, clearer camera-permission errors, and a reset button after each scan.
- Notifications: unread badge clears reliably, mark-all-read action.
- Empty, loading and error states on every page; mobile layout pass on dealer queue table.

## Technical notes

- Database migration: add `district` and `collection_code` to `profiles` (code auto-generated by trigger, backfilled); rewrite `allot_entry` to cancel the consumer's other waiting entries in the same transaction; add a partial unique index preventing duplicate active entries per consumer/depot; delete seed depots.
- Demo users created through the auth admin API from a one-off privileged server routine, then their profile/role/depot rows written in the same call (auth users cannot be inserted by SQL migration).
- Floating QR uses the existing `QrScanner`/`qrcode.react` setup in a shared `QrFab` component mounted in `AppShell`.
- New route `src/routes/_authenticated/profile.tsx` with its own head metadata.
